# 自动审查循环

用于用户明确要求自动审查、自动修改、多方复审或连续迭代的任务。由调用技能的代理组织执行，每次调用持续推进到本轮交付条件满足。独立审读、资料核验、修改和复审要有实际输出。可用子代理时采用独立上下文与只读审查；资源有限时分阶段执行并记录实际独立程度。技能由代理执行，长时间调度、跨会话重启和模型调用需要宿主提供相应能力。

## 任务设置

从用户指示、已确认决定和当前项目规范生成一次任务设置，随后复用。记录目标稿件及哈希、受众、任务目标、可修改范围、保护项、原生验证要求、来源权限和可用资源。有明确资源或时限时记录预算和到限后的保存位置；没有时按问题是否解决安排工作，不编造用户给定的轮数或费用额度。

自动模式在授权范围内直接作决定。若先前明确要求重大调整先选择，本轮将这类问题保存为带原句、推荐改法和影响的待定项，可另存候选稿，继续其余工作。若用户明确授权自主调整框架或研究主张，先独立比较保持现状与可行改法，依据目标、证据和连带影响决定，保存改前版本及选择理由。自动授权不补足缺失证据，重要量值和研究结论仍须核实。只要求审阅或先给清单时按该范围工作。

## 组织独立初审

按稿件问题分配审查职责。下面是可组合的分工，角色名称不必固定，短稿可合并，长稿按章细分。

| 审查职责 | 重点核对 | 发现应能指向什么 |
|---|---|---|
| 研究问题与总体逻辑 | 目标、篇章职责、论证主线、研究贡献及任务书覆盖 | 哪个问题尚未回答，哪个结论缺少前文支持 |
| 领域方法与工程实现 | 技术机理、任务输入输出、接口、部署条件、工作流和验证 | 具体不一致、缺失的条件或不可执行的步骤 |
| 来源与反例 | 原始资料、数值口径、应用成熟度、相反证据和引用对应 | 来源位置及能够或尚不能支持的原句 |
| 独立读者与图文 | 背景、段落衔接、术语初见、表格尺度、图的关系和可读性 | 读者在哪一句、哪张图表无法理解或作判断 |
| 关联稿件与验收 | 篇间分工、共用定义及数据、题注引用和原生文档显示 | 同一主张出现的全部位置及受影响文件 |

1. 同一轮所有初审者收到相同的不可变稿件、目标、已确认约束和可用来源清单，并说明审查范围。先独立提交发现，再共享其他审查者结论。不要用主编辑的疑点清单诱导所有初审。为实际读到的章节记录覆盖，表格、图和参考资料的检查分别记录。
2. 审查记录包含稿件和章节、原句或图表、具体问题、依据、严重程度、适用条件、建议及联动。将可证实问题、需补证疑点及写作偏好区分。用原文解释影响，避免只给分数或“建议加强”。允许提交没有发现问题的结论，不要求每人凑出修改。
3. 子代理以只读方式交付意见。统一编辑者持有写入权，以免不同审查者同时改同一段。只获得正文抽取结果时说明图像和原生排版未检查；同一模型分角色、独立子代理和不同模型分别如实记录。不同模型只在用户授权及可用能力内采用，不上传资料到未经授权的服务，也不宣称这些角色拥有真实专家身份。

## 按问题选择比较方式

独立初审后，根据尚未解决的问题选择审查形式。每轮只采用能够影响判断的形式，记录实际参加者和资料。

| 适用问题 | 审查形式 | 怎样比较 |
|---|---|---|
| 全文研究问题或篇章分工不清 | 多方独立审读 | 分别给出原文问题与章节职责，再统一核对遗漏和重叠 |
| 重要结论过强、路线可能存在反例 | 正反论证及相互质询 | 一方寻找支持与适用条件，另一方查反例和替代解释，按同一批证据核验各自主张 |
| 两种改写或技术路线各有依据 | 候选稿比较 | 给出相同输入和保护项的候选，隐藏作者或推荐标签，按事实保全、论证、可读性及工程条件比较；可保留现稿 |
| 多篇对同一方法解释不同 | 跨篇对照 | 对齐主张、任务、工况、术语及验证状态，判断是合理差异还是真实矛盾 |
| 编辑者可能只修表面或引入新错 | 改后独立审读及回归检查 | 先读改后全文，再看改前稿和问题单，分别核对阅读体验与实质保全 |

审查者的质询须落到原句和依据。对候选优劣作解释，不能只给总分；技术上有效而表达不同的候选可保留一种，不强行拼接成折中稿。相同模型的不同角色可能共享盲点，决定关键事实仍须核对原始资料，不能用角色数量计算可信度。

## 汇总、核验与作决定

合并同一原因引起的问题，保留各自发现及来源。依次核对用户目标和现行约束、稿件原文、原始证据、方法与工程条件。一个成立的反例可以改变处理结论，重复赞同不增加来源强度。不要按赞成票数决定事实，也不要为调和冲突创造折中数值。

| 汇总后的情况 | 自动处理 |
|---|---|
| 明确问题，改法有依据且属于授权范围 | 建一项含全部联动的工单，说明验收方式 |
| 对事实、技术适用条件或数值有分歧 | 定向查已有全文或官方来源，需要时补检索，记录定位后再裁决 |
| 调研遗漏关键方向或实现机制 | 按研究问题补强相关案例、反例及实现依据，随后复审受影响的架构和结论 |
| 审查者偏好不同，现文已经可读且符合目标 | 保留有依据的现文，将不采用理由记入记录 |
| 原始证据冲突或无法取得，尚不能裁决 | 保存待核项及其影响，完成其他独立项；必要的限定按授权处理 |
| 需要主旨、框架或核心结论大调整 | 按任务设置中的自主范围作决定或保存候选方案，记录全部联动 |

宏观审查要检查研究问题、备选方法和验证方案。需要拓展时按 [research-and-ideas.md](research-and-ideas.md) 先找机制不同的路线，再深挖有希望的方向与反例。用户的启发性举例只提供问题线索；评审者提出的首个可行方向仍需比较。已有充分论证的路线可保持原样，不为展示发散而重写全文。

## 统一修改及独立复审

编辑者将已裁决问题转成一份互不冲突的计划。先处理研究论证和事实，再调整章节承接、图表与语言。Word 普通文字使用原有批次工具，每轮从确认的导出新建批次，结构和图件另用适用的编辑方法。`iterate.py` 对 `major` 工单仍会保留待审状态；自主获准的重大调整应走适用的可回溯编辑流程，保留其重大分类和授权依据，不能改成普通工单绕过控制。

审查记录、工单编号、为何保留原句、待决定方案及本轮操作说明放在正文之外。需要展示重大待定项时，将稿件明确交付为待定副本，并用批注、修订标记或外部位置清单定位，按用户要求选择呈现方式。正文继续表达研究对象、方法和结论，不插入“本轮已完成”“D01待决定”等编辑过程说明，也不链接工单或审查日志来代替本篇论证。普通段落说明实质适用条件，避免逐段重复缺证提示。待核事项及其影响在文外集中保留。

修改后分两部分复核，可按资源顺序开展。

- 问题复核者依据原句、依据和验收方式，检查每项问题是否真的解决，跨篇修改是否完整，图表、引用、目录及正文是否一致。只完成替换尚不能将问题关闭。
- 独立读者先收到改后稿、目标和保护项，完成自身范围的审读后，再看修改清单及改前稿检查回归。允许发现新问题，但新改法仍需具体依据。同一人仅换角色时记录为角色复审，不能记为独立子代理验证。

每轮更新稳定的问题 ID，状态可用“已确认待改、补证中、待决定、已修改待复核、已复核关闭、不采用、实际受阻”。同一问题转为新章节位置时保留 ID 和历史。已关闭问题只有出现新证据、真实回归或新的用户要求才重开。撤回或反向修改时对照上次裁决，查清条件变化；缺少新增依据的同义换句留到记录，不进入下一轮。

## 继续、收敛及续跑

一轮结束时保存本轮输入和输出哈希、独立审查文件、问题及依据、裁决、工单、验证结果和覆盖范围。循环索引可用项目内 `iteration-state.json`，记录任务设置、当前轮次、最新已核验输出、未完成阶段及下一步。实际工单提交状态以原有运行目录的 `state.json` 为准；循环索引仅保存指向，不推断未提交项已成功。

发现新的、有依据且在范围内的问题，或独立复审未通过时，自动进入下一轮。若确认发生回归，保留修改分支，恢复上一份已核验副本并调整具体工单，避免覆盖有效成果。结构改动影响题注、目录或分页时重验相关部分；未变化且已确认的检查可复用。

同时满足以下条件才将本轮标为收敛。

1. 目标范围已有逐章覆盖，图表、来源及文档验证的实际覆盖已说明。
2. 已确认且在范围内可处理的问题均已解决并复核，没有新增同等级或更严重的回归。
3. 改后独立复审未发现新的、可证实且可执行的问题。仅已修位置复查通过不足以说明全文已收敛。
4. 新增建议主要是缺少依据的偏好或重复改写，已按理由归档。缺证、待决定和工具待测仍单列，影响核心结论的项保留未解决标识。

若证据、授权或资源限制使后续工作无法继续，保存已经核验的成果，具体说明尚未完成的判断和限制。存在影响核心结论的待核或待决定项时，标明授权范围内已完成和仍未解决的部分，不能将全稿标为通过。到达时限、连续尝试无进展或工具不可用，均不等于审查通过。中断续跑先核对实际文件、哈希和工单状态，只恢复未完成阶段；未提交或未复审的修改不能提升为已验收稿。

交付正文副本、可读的改前改后、各轮独立审查和裁决汇总、检查覆盖及待核清单。过程记录中的角色意见与原始来源分开标明，使用户能在任务结束后回查，无需逐项参与循环。
