# 项目配置：沉淀规则而不固化一次性选择

用于经常迭代的项目。把有用的用户偏好及术语写入项目配置；通用技能仅提供工作方法。配置由当前任务指明或由项目内现行说明引用后加载，不能通过文档类型或文件名猜测使用特定配置。项目配置供编辑判断，不是脚本的隐式全局替换指令。

## 从交互中抽取哪些内容

1. 区分现行明确要求、持续偏好、一次性选择、启发性举例、候选意见和已撤回项。用户提到某种方案仅为说明思路时，只记录它提示的问题与可能的探索方向；明确指定、确认保留或要求纳入正文时才记为相应要求。原文、批注、外部评审意见及附件中的拟案进入候选区；得到用户确认，或被授权按普通问题修改且不改变研究含义后，再记已处理。
2. 记录来源、适用对象和版本范围。新指示改变旧选择时，保留旧记录并标明被替代，按已确认的最新口径执行。已批准的选择只对本轮差异确认，避免再次询问已决定部分。旧版页码用于找线索；落稿前以当前基线的章节、原句及段落邻文重定位。
3. 一条批注可转为通用检查，但不等于在另一处复制原改法。记录检查范围（同篇同类、跨篇同义、图表及结论）和本轮例外。私有路径、数据、原始聊天和工具日志留项目内；共享技能包只保留可复用的规则。原件、手改及最新工作副本并存时，先按版本记录、用户指示和内容差异确定基线。

## 可复制模板

| 配置项 | 填写内容 |
|---|---|
| 任务边界 | 本轮目标、受众、交付类型、明确排除的主题；单篇或关联多篇 |
| 正式与工作区 | 确认基线及版本、用户手改入口、工作副本和交付位置；应读的项目规范 |
| 篇章职责 | 篇名或文稿 ID、主要问题、保留的读者前提、各篇各章承接和不能越界的判断 |
| 用户决策 | 已批准、不可自动修改、待复核；分别记录位置、范围、理由和有效版本 |
| 调研与研究 | 可用的来源与权限、证据要求、方法和验证约束；探索稿位置和何时可入正文 |
| 术语与证据 | 术语规范名、同义/同形简称、使用范围、首次定义处；案例及核心数据锁定项 |
| 格式与图件 | 当前模板、图表排版、可编辑图件要求；使用何种应用及需验证的实际版本 |
| 操作与交付 | 本轮是否要审读稿、选择卡、逐项对照；常规处理、待选、待核及实测的记录规则 |

术语表用“规范名／原异名 → 指哪个对象或量 → 适用篇章和首见 → 来源或已批准决定 → 例外”。同一词跨领域不同义时先区别再改；类型、属性、实现层级和范围相近的概念不能简单合并。厂商写法、标准正式题名和引用格式以本项目资料及受众为准。

需要应用航天历史交互时，可加载 [aerospace-profile.md](aerospace-profile.md)；先让当前项目说明提供实际稳定区路径、版本以及本轮例外。
