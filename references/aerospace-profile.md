# 可选配置：航天调研项目的协作与写作偏好

适用于用户明确指定的航天调研项目。这里是交互中的稳定做法，不是具体文稿的章节冻结表、技术定义或版本清单。当前用户指令、已确认基线与项目现行规范优先；另一个任务不继承既往访问权限、发表意图或软件验证结论。

## 研究分工与边界

- 跨行业调研篇以案例来源、做法、验证、适配与差异比较为主。案例叙述不与航天借鉴反复交错；汇总证据后再谈对目标任务的借鉴。对案例有疑点仍可保留已核实的方法与实质，说明边界及待核部分，不为统一行文大批删例。
- 多学科仿真篇从总体任务、资源条件与约束分配过渡到专业分析组织和工程工作流，不以辅助工具替代系统目标。分别写清串行集成、物理反馈、计算调度与设计优化。保持已批准的贯穿例子和数值；新解释不能默改条件、单位或结论。
- 智能辅助设计篇从工程输入、设计任务、方法到工具及验证。首期使用已有资料、网络或工具与后续新增能力要分别写；原生设计模型与按工程规范组织的数据模型按作用区分。正文以具体对象、约束、输入输出和复核职责解释“辅助”，示意图和拟议功能不能算已有落地效果。
- 天地协同篇主要围绕在轨运营，研究状态更新、任务预演与验证等目标。区分已公开的工程应用和拟开展的在轨数据辅助后续优化；制造或装配案例只有能支持当前问题时才保留。第 2 至第 4 篇的摘要性内容通常归入第 1 章，仍以本次文稿现行结构为准。
- 不因概念或案例共享而把关联篇章合成一本；每篇解释适用任务、必要接口、判断前提及所用原始证据。跨篇回扫技术断言；同一术语的不同任务层级不要强行统一。发现争议时按已批准定义或原始证据提出处理方案。

## 从交互转成复用规则

| 反复出现的用户意图 | 本轮怎样落实 |
|---|---|
| 局部反馈应推广到同类问题 | 核对术语、引图、指标、相邻段、表格与结论；记录检查过但保持原样的范围，避免机械全局替换 |
| 在选择前看得出会改哪里 | 以现稿的节号、原句、表图号和证据定位为准，给实际改法和影响。原有例子、保留项不随重新排查被悄悄改动 |
| 可读性优先于术语堆砌 | 先讲任务目的、对象和背景，再讲实现、例子与结果；写明谁做、处理什么、怎么判断。并列项同维度，标题短，技术限定就近解释 |
| 调研想看有代表性的工程做法 | 查实际任务及同义词，兼顾国内外、标准、机构资料与原论文。图选真实关键界面、模型、试验结果或关系；服务观点再放图，不以会议照片替代技术证据 |
| 引用和图表要帮读者作判断 | 相邻事实可合并引文，关键新数据保留可追溯出处；不需重复单列图源时仍在正文、文献或证据记录中留定位。表用同一尺度比较，流程图表达输入、先后、分支、反馈；箭头标注具体返回内容 |
| 用户举例用于启发，不限定研究路线 | 先抽出例子背后的工程问题。把第一个可行点当对照，继续找跳出既有工具或流程的候选，深挖其作用机理、依赖、失效场景及最小验证；解释取舍后再推荐。除已明确要求采用或保留的例子，其余按论证价值决定是否入稿。拟改变重点时先展示原文和备选方案 |
| 中断后先辨认已保存成果 | 先核对基线、工作区哈希、记录、软件是否保存重开以及待办；只接续未完成事项。不因错误信息重跑并覆盖已完成文件 |

## 格式与原生验证偏好

- 以确认的 Word 模板为准，默认 A4，中文正文用宋体，标题及字号按模板，西文按 Times New Roman，图表题居中，保留页脚页码；不把报告版本号写进封面正文。篇幅、压缩目标、具体受众和被锁定格式按当轮记录，不能提升为通用硬规则。
- 图件改动时同步核对 Word 图题、图号、可编辑源图和实际显示。优先黑白打印也清楚的分组、留白、字体和折线，区分并行、反馈及调用方向。旧图沿用则说明沿用内容及证据，不说成当轮已经重新测试。
- 可原生打开时更新 Word 的正文域及整个目录、保存、重开，核对编号、书签、引用、分页和图文显示。需要时用 Visio 原生保存重开并检查对象可编辑；记录实际应用版本。没有在指定目标版本实测时，保持待测状态。
