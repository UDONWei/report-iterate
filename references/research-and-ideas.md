# 调研、研究与方向发散

在任务包含补调研、研究路径设计或方向探索时读本页。局部润色发现缺证，只登记疑点；用户已授权且在主题范围内的补调研可直接做。方向探索与正文修订可以并行推进，产物、证据和批准状态分别记录。

## 先判断缺的是哪一种工作

| 读到的问题或用户目标 | 做法 | 得到什么 |
|---|---|---|
| 原有事实、方法效果或案例应用含糊 | 查原始来源及对应图表，核对对象、工况和结论边界 | 可直接证实的改写；找不到证据的缺项 |
| 担心少了常用方法、重要应用或反例 | 按工程或学术问题建检索矩阵，不按现有目录机械补量 | 代表性案例、取舍原因、调研覆盖与未覆盖条件 |
| 已有方向，论证停在架构示意或想法 | 明确问题、基线、输入输出、判据、验证和失败后怎么办 | 能判断是否值得做的研究方案 |
| 现有方向可能太窄，或需寻找不同研究路线 | 分别定义目标与约束，发散并保留探索稿 | 有区分度的备选方向、必要前提、淘汰理由和需要选择的事项 |

## 调研：从问题到可引用证据

1. 从研究目标、任务书及现文列出缺口。每个检索问题写明将影响哪个判断或范围、已有资料、有待找的反例，以及新证据可能影响哪些篇章。局部补证不必做完整综述；进行系统综述时事先记录数据库、时间范围、检索式、筛选和完整性限制。
2. 先看用户给的原文、项目资料及正式规范；对公开调研，交叉使用中英文名称、同义词、具体任务、软件/标准名、部署或验证等检索维度。按主题覆盖国内外或不同类型实践，按证据与目标选例，避免为了覆盖数量收录薄弱案例。遵守当前资源授权，既往的登录授权不自动转用于新项目。摘要、新闻或产品宣传只能提供线索或其所明示的事实，不能填补全文未核实的机制和实测数字。
3. 核对原始论文、标准或机构技术记录的版本、节、页、图表和适用范围。一个案例只保留解释价值所需的细节，依次明确目标、对象、输入、方法和关键接口、输出、验证与边界。区分工程部署、受控试点、算例、比较基线、参考模型及拟议工作。矛盾证据并排写明各自的对象、时间和口径；影响核心结论时给用户选择，普通笔误按已核实的原文改。
4. 用证据表连接检索与落稿，保留无法获取全文、来源冲突和排除原因。先完成本轮足以支持结论的覆盖；继续检索只有在能补关键证据、反例或代表应用时才有价值。不能验证的数字、范围或效果不补造。

## 研究：让论证可以被复核

- 先写任务、传统做法或当前基线及实际瓶颈，再给候选方案。把共用输入、模型及接口、校核输出和责任人说清。先说明可行判据及硬约束，再写可行之后的偏好或不同权衡。明确系统层、专业层和工具实现层的关系；计算资源、物理机理、优化流程和验证证据不要混为一个维度。
- 设计能区分备选方案的对照：固定哪些条件、比较什么指标、遇到不满足判据要采取什么措施。涉及自动化时可比较人工流程、同条件的确定性工具、以及增加拟议方法后的增益；把核对、返工、部署维护和数据准备成本计入。实测少时用可操作的验证计划，标注已验证、不确定和未执行状态。
- 已用数据调定参数之后，另用未参与调定的工况、对象、时段或测量核验。说明可用的基准、评价指标及失败条件。示例输入、已核实测量和推断分别标识；如果验证不可执行，具体说缺什么，不把假设写成完成结果。
- 对照研究目标和任务书检查已有、薄弱、缺失及不适用项。把必要论证补到承担它的章节；保留用户指定的例子和已确认边界。承接关系用本篇能读懂的数据、条件、行为与结论表达。

## 头脑风暴：先发散，再收敛

1. 先把当前写法或现行做法作为可保留的基线。区分明确要求、工程约束和启发性举例。对用户随讨论提出的构想，先问它想解决什么、哪些条件才让它有用，哪些只是例子采用的实现假设。把问题和判断标准带到新方向，不自动继承例子中的工具、阶段或章节安排。
2. 找到第一个可行点后，继续沿不同机理或层次发散。可换介入时机、系统边界、输入与反馈、人工与工具分工，或者反过来问哪项改进能让原问题不再发生。对照现行做法和可行的简化方案；检查替代方向是否真的改变机制，而非给首案换名字。例如，用户举“自动生成候选以缩短设计时间”时，还可研究能否前移约束核对以减少无效试算，或复用已验证的设计模板以减少重复工作。例子仅帮助打开问题，比较范围取决于实际瓶颈。
3. 对有希望的方向做同等口径的深挖：解释为什么可能有效，能改善哪一步、把成本或风险转移到哪里，最可能在哪种工况失效，什么数据或反例会推翻判断，以及最小怎样验证。区分已有证据、条件推断和待测假设。根据硬约束、机制差异、证据和验证成本作取舍，说明何时值得把两个方向组合；不因首案能实现就停，也不为凑个数罗列。若最后只有一条值得推进，说明查过哪些其他方向、为何排除，以及什么条件变化后值得回看。
4. 默认把发散结果单独保存为探索稿；记下比较基准、未采用的方向和原因。用户举例和探索所得都按证据、相关性及能否帮助正文论证决定是否纳入。与本轮明确目标一致、依据充分且不改变主旨的普通补充可转成工单；改变主旨、章节框架、核心结论或承诺范围的先给选择。不把路线探索扩成用户没有要求的普通修订步骤。

建议事项的最小决策卡：`篇名／节号／原句或表图 → 为什么影响判断／证据 → 保持现状与可行改法 → 各法对数据、篇章、关联文稿和验收的影响 → 推荐及适用条件`。只让用户选择有实际差异的改法，并同时推进独立的普通修改。
