# 单篇论文和关联报告的编辑检查

用于决定改什么、改到哪以及从哪里验收。检查到问题与授权执行是两件事；问题清单也不能替代改后的原生文档检查。

## 先按读者会问的问题定篇章职责

| 场景 | 先建立的论证图 | 复核方法 |
|---|---|---|
| 单篇论文 | 问题 → 现有方法及缺口 → 本文的方法或主张 → 设计、数据、结果 → 讨论、结论和边界；标出摘要、图表、正文对同一结论各承担什么 | 摘要和结论有正文支持；样本、变量、控制、数据处理和结果能追溯；方法和观察不倒置；讨论解释替代原因、局限和可推广条件 |
| 单篇工程报告 | 任务及决策 → 调研或输入 → 候选与约束 → 评价和取舍 → 实施、验证及后续边界 | 读者能看出为什么选、怎样做、谁复核、哪些结果已确认；流程图与实际工作通道一致 |
| 多篇关联文稿 | 先按篇名、服务对象、承担的主问题、可引用事实和明确排除项定分工；记录案例、定义、共用数值、假设和术语的出现位置 | 对同一主张比较范围、工况和验证状态；各篇独立读得懂，减少只复述其他篇的文字。部分背景重叠可能有必要，保留本篇论证必需的前提 |

章节用一行记录“回答的具体问题、前置输入、可交付的判断、交给后文的内容”。核对关键概念先定义、再使用，图表先交代其作用，贯穿示例在后文仍使用同一对象、条件和数值。调整句段次序能解决的问题先考虑局部改法；改章职责、增删主要结构或核心判断须给决策卡。

## 阅读时区分三类判断

1. **可核实的硬错。** 检查输入输出、同一技术量的范围或单位、题注与正文指向、先前已核实的术语、显然的标点错误。不要把 Word 域缓存、章节号抽取缺口或图号开头的正文当真错；以文档结构和实际显示核对。标点空格、定点拼写和意思明确的术语是普通修订；涉及量值或论证结果的“硬错”先查依据和用户权限。
2. **需要上下文判断的写作问题。** 空泛词改成执行者、对象、输入和可观察的结果；歧义可写出指代对象。段落按问题转折、因果与话题切分，长短不作为硬指标。“见图”已有清晰目的时保留；图后解释补读者需要的关系，而非每图再说一遍。表头、各行与结论要在同一尺度；结论可回顾必要发现，仍须受前文支持，不能为避免重复而添加新观点。
3. **论证、证据和边界问题。** 将“缺少证据”和“论证错误”分开；未实测、替代解释、适用条件或冲突证据须记录，不能靠润色把疑点消除。可以明确表达已有结论的适用范围，但若改变关键信息、研究主张或交付承诺，先给用户原文、影响范围及可选改法。见 [research-and-ideas.md](research-and-ideas.md)。

## 工具介绍与配图

先交代谁在什么条件下用什么工具完成任务，以及哪一步仍然慢、容易出错或难以比较。写明新工具要解决的那个问题。一个工具含多项功能时，用读者熟悉的设计任务作小标题，配相应界面介绍输入、操作和可用于判断的结果，再串起完整案例。

| 核对对象 | 落到文中的判断 |
|---|---|
| 传统做法与改进 | 向使用方或原始资料核对现用流程，保留已具备的软件能力和原有约束。例：现用排班软件已能覆盖各岗位。若新工具可在人员请假后只重排受影响班次，改进落在重新排班和复查的范围。 |
| “智能”“敏捷”“最优” | 说明工具替人完成哪一步匹配、筛查、搜索或排序，哪些决定仍由人作出；指出变更后哪些数据和结果可复用。比较优劣时写明可行条件、评价目标与搜索范围，声称最优须有穷举、界限一致等相应依据。 |
| 效果证据 | 区分现场经验、可复现的算例、实际工程应用和拟开发功能。保存重开可验证结果能读取；时间、质量或可靠性改善须在可比的输入、约束、运行条件和交付要求下验证。依任务记录完整用时、失败重试、人工复核或返工。 |
| 界面及输出图 | 分清实际操作截图、软件直接导出、依据数据绘制和界面构想。说明进度用运行中的截图，展示实际输出用该工具直接导出的成品。按读者用途选择导出项，过程编号和诊断信息留在核对资料。图、表取自同一版结果，图注交代所示对象；缺合适原图时记录缺口。 |

比选时分开写硬性约束和可行方案间的优选指标。改变权重可以改变候选次序，未核实的硬性要求仍需逐项确认。校准用的数据与独立验证数据分别交代。软件间传值一致、模型重开成功、实物验证通过，各自只支持对应环节的结论。

图表按读者的使用场景检查。流程图的箭头应能读出传递对象及方向，避开无关框和文字；对比图的视角、尺度及标注适合所作比较。更新域后在实际分页中核对正文引图句、题注、编号、交叉引用的字号及换行。沿用原图时记录已有核验结果；题名或编号变化时同步检查正文引用和图页索引。

## 普通修订后的联动检查

- 从变更位置核到前后论证、相关术语初见、图表正文与题名、文献引用、结论、摘要及附录。多篇再核对其他篇出现的同一主张和边界；同一词不代表同一变量。同类搜索可发现候选，不能自动批准批量替换。
- 批注纠正对照方法时，连带查任务说明、功能例子、小结表、对照试验及结论。再到关联稿找承担相同叙述作用的位置。公开案例若确实以人工方式作对照，保留原研究范围与依据。
- 工单放一条具体问题与可核实改法。保留现文、邻文、定位、关联位置、验收方式和依据。若项目要求字面保护、修订痕迹或正式批准，以对应方式输出。还要分清工具扫描覆盖、人工阅读和应用实测各自做了什么。
- 多份评审提出同一问题时合并处理，保留各意见编号供对照。要求互相冲突（如同一表格同时要求保留和删除）时列出冲突的原句，先执行兼容的局部修订，由用户决定冲突项。
- 全篇审读逐章记已检查、未涉及和需补证的范围。局部期次复用确认未变化的旧结果；若变更影响引用、目录、分页或图文位置则重验相关部分。达到本轮目标且回扫无新的、已证实的授权内问题时结束，不用固定的润色次数充数。
